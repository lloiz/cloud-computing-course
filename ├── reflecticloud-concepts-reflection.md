# Reflection Paper: Cloud Computing Concepts

## Cloud Services I Use Daily

In my daily digital life, I interact with several cloud-based services that have become essential tools. Three notable examples are:

1. **Google Drive** - Used for storing and sharing documents, photos, and files across all my devices.
2. **Spotify** - My primary music streaming platform that provides access to millions of songs.
3. **GCash** - A mobile wallet application for financial transactions and online payments.

## Service and Deployment Model Analysis

**Google Drive (SaaS, Public Cloud)**

Google Drive functions as Software as a Service (SaaS) because users access ready-to-use storage functionality through a web interface or mobile app without managing underlying infrastructure. There's no need to provision servers, install software, or handle maintenance—Google handles everything. It's deployed on a Public Cloud model because the service is offered to the general public over the internet, with resources shared among multiple tenants.

**Spotify (SaaS, Public Cloud)**

Spotify exemplifies SaaS since it provides a complete music streaming application accessible via web browsers or mobile apps. Users consume the service without concerning themselves with server management, database administration, or software updates. The platform operates on a Public Cloud infrastructure, serving millions of users globally through shared resources distributed across data centers.

**GCash (SaaS, Public Cloud)**

GCash delivers financial services as a SaaS offering, allowing users to transfer money, pay bills, and make purchases through a mobile application. While financial services require higher security, the underlying infrastructure remains on public cloud platforms that handle scalability, security, and compliance requirements. This makes it a Public Cloud deployment, as the service is accessible to anyone who registers.

## Git & GitHub for Cloud Projects

Version control systems like Git, particularly through platforms such as GitHub, are indispensable when working with cloud infrastructure. They provide several critical benefits:

**Infrastructure as Code (IaC) Management**

When managing cloud resources, teams define infrastructure through configuration files (e.g., Terraform, CloudFormation). Version control allows tracking every change to these files, enabling rollback to known good states if errors occur.

**Collaborative Workflows**

Cloud projects typically involve teams of developers, operations engineers, and security specialists. GitHub facilitates collaboration through pull requests, code reviews, and branch protection rules. Multiple team members can work simultaneously on different aspects of cloud infrastructure without overwriting each other's changes.

**Change Tracking and Error Prevention**

Every modification to cloud configurations is logged with detailed metadata—who made the change, when, and why. This audit trail is crucial for compliance and troubleshooting. Through continuous integration pipelines triggered by GitHub, infrastructure changes can be automatically tested before deployment to production, preventing configuration errors from reaching live environments.
